# 同仁操作指南

本工具協助整理「產品文件如何對應規範、哪些地方不同」，由人工確認結果後再交付。Windows 一般同仁請下載 [完整 Portable ZIP](WINDOWS_PORTABLE.md)，全部解壓縮後雙擊 `Start.bat`；Python、模型服務及入門模型已內附。原始碼版則請先由熟悉電腦的同仁完成環境與模型設定。

## 1. 先試用合成示範

1. Portable 版雙擊 `Start.bat`，等待內附模型載入與瀏覽器開啟；其他版本使用對應作業系統的啟動檔。
2. 使用畫面中的一鍵示範入口，系統會載入合成產品與規範並自動執行示範比對。
3. 查看排序、差異與產品引述。
4. 任選一筆結果，輸入覆核者與意見，確認或更正判定。
5. 匯出 HTML，確認報告中包含原判定、人工結果及歷史。

示範不會呼叫本地模型，採固定規則產生可重現的結果。它只供學習介面及檢查作業流程，不代表 AI 的判斷能力。一般上傳的文件不能使用示範模式冒充正式結果。

## 2. 準備文件

| 角色 | 準備內容 |
|---|---|
| 產品 | 本次要評估的單一產品規格文件；若資料散落多份，先整理成一份可追溯的彙整文件 |
| 規範 | 一份或多份要比較的技術規範；不同版本請使用清楚的檔名，例如 `介面規範_v2_202609.pdf` |

可使用有文字層的 PDF、Word `.docx`、Excel `.xlsx`、CSV、純文字或 Markdown。單檔上限 30 MB。舊式 `.doc`／`.xls`、加密文件與圖片，不應直接視為可解析文件；請先轉成支援格式。不要只改副檔名。

準備時請注意：

- 保留文件版本、條文編號、單位、表格標題與測試條件。
- 掃描 PDF 必須先做 OCR 並核對文字；本程式沒有內建 OCR。
- 多個產品合併在同一份文件，可能讓模型混用不同型號的證據，請先整理。
- 若某個規範包含太多不同主題，可以預先整理成每條要求一行／一段，保留原條號。原文件也應由人員留存供核查。

## 3. 開啟與設定模型

**Windows Portable：** `Start.bat` 會啟動內附模型並設定連線。直接使用「開始本機模型比對」即可，不必安裝或開啟 LM Studio，也不必購買 API key。想更換模型時，先停止程式，將相容 GGUF 檔放入 `models`，雙擊 `Choose_model.bat` 選擇後再啟動；詳見 [可攜版指南](WINDOWS_PORTABLE.md#換用較大的模型)。內附 2B 模型僅供初篩，正式工作應完成代表性文件驗收。

以下設定供 **原始碼版或自行管理本機模型服務** 使用：

1. 在 LM Studio 或相容本機服務中載入模型並啟動 API Server。
2. 開啟本工具的模型設定。
3. 填入服務顯示的 API 基址，例如 LM Studio 常見的 `http://127.0.0.1:1234/v1`。Bionic 請填自己的實際位址。
4. 測試連線、選擇或填入模型 ID，儲存設定。

API 基址必須是 `localhost`、`127.0.0.1` 等 loopback 位址，不能使用公司伺服器 IP 或雲端網址。若你的 Bionic 只提供聊天介面而沒有相容 API，本工具不能直接接入，請由 IT 使用 LM Studio 或相容服務。

先採用預設參數。若 IT 調整：

| 參數 | 用途及注意 |
|---|---|
| Temperature | 預設偏低，減少隨機變化；不代表完全可重現 |
| Max tokens | 模型單次輸出上限；過低會讓 JSON 或差異清單被截斷 |
| Timeout | 每次 API 的等待時間；模型很慢時可提高，取消也可能等待這段時間 |
| Context chars | 文字視窗大小，單位是字元而不是 token；模型 context 太小可能出錯 |
| Structured output | 要求模型以結構化 JSON 回覆；是否支援取決於模型服務 |

改參數後請再用相同的代表性文件測試。不要只因為能連線就視為可正式使用；`/models` 成功不代表模型能正確完成規格比對。

## 4. 建立專案、上傳與確認擷取

1. 建立有明確名稱的專案，例如 `48V控制器_A版_介面規範初評`。
2. 上傳一份產品文件，選擇「產品」角色。
3. 上傳一份或多份規範文件，選擇「規範」角色。
4. 對每份文件按「預覽並確認」，對照原檔與警告。
5. 確認文字及單位足以比對後，勾選聲明並確認原文。

確認時至少抽查：首頁、最後一頁、重要數值、表格、符號、上下標及跨頁條文。PDF 的位置以頁碼呈現；DOCX 常用段落／表格位置；XLSX 以工作表／列呈現。這些位置方便返回原檔，並不等同所有格式都有精準的條號解析。

如果缺頁、數字錯誤或表格對應不清楚，請先修正文書來源再上傳。按下確認只是記錄「允許使用此擷取結果」，不是系統已保證解析正確。

## 5. 啟動比對並查看進度

選擇要比較的規範，開始正式比對。系統會將每個規範文字區塊，逐一對照產品文件的全部文字視窗，完成後即儲存一列。

- 進度中的「已完成／總數」代表完成處理的規範區塊數，並非已確認合規的條件數。
- 模型無回應、回傳格式錯誤或無法驗證證據時，該列標記「待確認」並保存原因。
- 若按取消，系統會等待正在執行的模型呼叫返回，再停止後續處理。不要預期立刻中止模型服務。
- 程式中斷後重開，可針對該次比對續跑，跳過已儲存的結果。若要重新評估已完成但失敗的列，請排除問題後建立新的比對。
- 後來上傳的文件不會改寫舊結果；更新文件後應建立新的比對紀錄。

所需時間與「規範區塊數 × 產品文字視窗數」大致相關。第一次請先測一小份代表性文件，確認速度與判讀品質再處理長文件。

## 6. 如何看「最接近哪份規範」

規範排序顯示「文件符合度參考分數」，公式如下：

`分數 = 100 ×（符合＋0.5 × 部分符合）÷ 全部規範區塊數`

「不符合」「文件未載明」「待確認」仍保留在分母，所以文件缺資料不會因為被排除而膨脹分數。已確認或更正的列以人工最終狀態計算。

請把分數與三件事一起看：比對是否完成、未載明與待確認項目是否很多、關鍵安全／性能條款是否符合。某份規範即使整體分數高，只要關鍵門檻不符合，仍可能不適用。此版本沒有替不同條款配置風險權重。

## 7. 逐筆覆核與歷史紀錄

每筆結果都應先閱讀規範原文，再檢查產品引述、位置、差異清單與警告。

模型自評信心只是模型產生的分數，並非經過校準的準確率；不要只因分數高就跳過覆核。

| 動作 | 什麼時候用 | 記錄效果 |
|---|---|---|
| 確認 | 同意 AI 判定 | 最終狀態維持 AI 判定，新增覆核事件 |
| 更正 | AI 判定錯誤或有新的人工解釋 | 選擇正確狀態並填理由，新增更正事件 |
| 重新開啟 | 需要其他同仁重看或撤回目前覆核 | 回到待覆核，有效狀態回到 AI 原判定；歷史保留 |

輸入可辨識的覆核者姓名。更正及重新開啟時必須填寫理由，建議包含原文件條號、判斷依據與尚待索取的資料，例如：「產品 P12 僅標示典型值，規範 4.2 要求全溫範圍最大值，改為部分符合，需向供應商索取測試紀錄。」

歷史採逐次追加，可依時間與版本追溯確認、更正與重新開啟。AI 原判定仍保留，不會被人工狀態覆寫。覆核者姓名為自填，不能當作已驗證的身份或數位簽名。

若兩個瀏覽器頁籤同時修改同一列，後送出的舊版本會被拒絕。請重新讀取最新狀態，再決定是否提交；不要直接覆寫別人的意見。

## 8. 匯出與交接

| 格式 | 適用情境 | 注意 |
|---|---|---|
| HTML | 讓同仁用瀏覽器查看／列印 | 包含全部差異與覆核歷史；是匯出當時的快照 |
| XLSX | 彙整清單、篩選及開會討論 | 包含 Results、History、Documents、Run 工作表；在 Excel 改字不會同步回系統 |
| JSON | 技術留存、重算或外部系統介接 | 包含結果、快照與歷史；本版未提供匯回功能 |

未覆核、待確認及未完成狀態也會出現在報告中，不能將其隱藏後當作全部完成。報告不包含 API 金鑰，但包含產品原文與規範內容，請依公司文件權限分享。

覆核後再匯出，才能取得最新人工結果。每次匯出會另存報告檔、匯出時間及 SHA-256，可以在「匯出與追溯」查看歷次匯出並下載當時的原報告。之前的報告不會隨後續覆核自動更新。

程式不會覆寫已封存的報告；這是應用程式的保存規則，不是防竄改簽章。資料夾的持有者仍可能在程式外修改檔案。

## 9. 常見問題

| 現象 | 處理方式 |
|---|---|
| Portable 雙擊沒有畫面 | 確認下載完整 Portable ZIP 並全部解壓縮；查看啟動視窗及 `logs`，依 [可攜版排錯](WINDOWS_PORTABLE.md#遇到問題時) 處理；此版本不需要自行安裝 Python |
| 原始碼版雙擊沒有畫面 | 保留終端機錯誤訊息給 IT；確認已安裝 Python 3.11+ 與依賴 |
| macOS 不允許執行啟動檔 | 由 IT 確認檔案來源並給予執行權限；勿繞過公司的系統控管 |
| 瀏覽器沒有自動開啟 | 使用啟動視窗顯示的網址；原始碼版預設為 `http://127.0.0.1:8765` |
| 端口被其他程式占用 | Portable 版會自動改用其他可用埠，使用啟動視窗顯示的網址；原始碼版可執行 `python launcher.py --port 8766` |
| 連線測試失敗 | 檢查本機 API Server、基址、模型 ID、API key，以及模型是否已載入 |
| 能連線但結果都是待確認 | 查看逐列診斷；可能是 JSON 支援、輸出截斷、timeout 或模型能力不足 |
| PDF 沒有文字／文字很亂 | 使用經核准的 OCR 或轉檔工具，人工核對後再上傳 |
| 比對很慢 | 先測小文件；由 IT 調整模型、量化、context 或硬體，勿只靠放寬 timeout |
| 取消後還在等 | 等待目前模型請求返回；超過預設 timeout 後應記錄失敗／停止 |
| 上次資料不見了 | 請 IT 檢查是否更換程式資料夾或 `SPEC_CHECK_DATA`；不要刪除舊 data |
| 要交接到另一台電腦 | Portable 版先以 `Stop.bat` 停止，再完整搬移解壓資料夾；原始碼版備份整個 data，於相容版本還原；不只複製 HTML |

關閉瀏覽器不等於停止服務。Portable 版請先等待比對完成或按「停止比對」，再雙擊 `Stop.bat`；已完成的結果會留在解壓資料夾中的 `data`。

備份步驟與安全邊界見 [README](../README.md) 及 [SECURITY.md](SECURITY.md)。
