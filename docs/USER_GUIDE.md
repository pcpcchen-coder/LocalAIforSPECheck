# 同仁操作指南：標準文件庫與產品風險初評

適用 v0.3。一般同仁不需要寫指令或安裝 Python。先依 [Windows Portable 指南](WINDOWS_PORTABLE.md) 準備程式與獨立模型檔，再雙擊 `Start.bat`。

本流程產出三類交接資料：**相關標準、需要優先覆核的差異、待補證據**。系統會保留所有分析範圍中的標準；由人員確認哪些繼續比對。AI 建議不等於正式認證。

## 1. 準備文件與工作資料

| 文件 | 建議準備方式 |
|---|---|
| 產品規格 | 一次一個產品／型號。若資料分散，先整理成一份保留來源標記的彙整文件，避免混用不同型號 |
| 標準與技術規範 | 保留文件編號、版本、適用範圍、地區、條文編號、單位、例外及測試方法；不同版本使用不同檔名 |
| 產品用途 | 準備預定用途、操作環境、目標市場及其他補充；不確定的資訊留為未知，不要猜填 |

可讀格式：有文字層的 PDF、DOCX、XLSX、CSV、TXT、Markdown。單檔上限 30 MB。掃描 PDF、圖片與圖面沒有內建 OCR；請先使用公司核准的工具轉成文字並核對。舊式 DOC／XLS 請另存為支援格式，不能只改副檔名。

## 2. 建立可重用的標準文件庫

1. 進入「標準文件庫」，上傳標準。已有舊版專案時，按「匯入舊版專案文件」並選擇專案，即可沿用原檔，不必重新上傳；相同內容及角色會重用。第一次建庫先用兩三份短文件測試，再加入整批文件。
2. 選擇萃取方式：按「抽取獨立項目」使用本機模型；或在文件「查看／確認」按「外部模型萃取（ChatGPT）」取得萃取包，依 [外部萃取指南](EXTERNAL_EXTRACTION.md) 取回 JSON 並套用。外部方式不必先做本機標準抽取。
3. 開啟文件原文與抽取結果，核對是否有漏字、錯位表格或沒有處理清楚的原文。
4. 補上文件版本、範圍、分類、地區等資料；未知的欄位可以留白。
5. 逐項檢查，必要時修改或拆分，再填覆核者與說明並確認文件。

抽取過程可查看執行現況、停止及續跑。關閉頁面或重啟後，可從文件列或文件視窗按「查看進度」找回該份文件的工作。已抽取的文件會沿用保存的項目；重新抽取會影響目前文件的項目與確認狀態，舊分析快照仍保留原狀。請先完成修改再建立正式分析。

建庫是共用的前置工作：下一次上傳新產品，可沿用這批已確認標準，不必重新上傳與抽取。此處的「共用」指同一個本機資料庫中重用，不是多人網路服務。

## 3. 檢查、修改與拆分獨立項目

每個項目包含名稱、參數、值、單位、運算關係、條件、例外、測試方法、關鍵性及來源引文。沒有原文支持的資訊不可自行補成已知值。

| 原文例子 | 應如何整理 |
|---|---|
| 輸入電壓 200–240 V AC，工作溫度 −20～60 °C | 分為電壓與溫度兩項，各保留完整條件與來源 |
| 額定輸出不低於 10 kW，但高溫時需降額 | 功率要求須保留高溫例外；不能只留下 10 kW |
| 依第 7 節測試，絕緣電阻須大於指定值 | 保留測試方法與跨章引用；尚未確定條件時標記待處理 |
| 範圍定義、術語說明 | 標為背景資訊，避免當成產品必須通過的獨立測試 |

修改項目時，引用必須確實出現在所指定原文區塊。拆分時為每個新項目保留來源；未涵蓋的原文會保留提示。系統會記錄修改者、原因及版本，不覆寫既有分析的來源。

**未解析／待處理項目不能被當作沒有要求。** 請補足內容或在確認文件時明確知悉警告；仍有不確定資訊會進入後續分析及報告。來源涵蓋檢查能提醒未被引文涵蓋的文字，但不能證明 AI 已理解每一個語意條件。

## 4. 上傳一份產品並啟動全庫初篩

1. 進入產品文件區，上傳本次產品，執行與標準相同的抽取、修改／拆分及確認流程。
2. 在「產品與分析」的產品清單按「用於分析」。新版介面建立全庫分析，初篩會涵蓋整個標準庫。
3. 填入用途、環境、市場及補充資訊；使用便於追蹤的名稱，例如 `控制器A_設計初評_202609`。
4. 選擇「候選項目比對（較快）」或「完整產品項目比對（較慢）」。下文分別稱為聚焦與全量比對。這個選項影響後續產品證據掃描，不會省略分析範圍內的標準初篩。
5. 開始初篩。所有參與分析的文件必須先完成抽取並確認。

系統為分析保存當時的文件、項目、來源、模型設定及人工抽取歷史。之後修改文件庫，不會自動改寫這份分析；要使用新版文件或不同模型設定，另建分析。

## 5. 確認哪些標準繼續比對

初篩結果分開列出：

- **相關性**：主題或要求是否與產品有關。
- **適用性**：用途、使用環境、規範範圍等條件是否足以支持適用。
- **理由及證據**：模型根據哪些資料判讀，還缺什麼資訊。

例如：高壓設備標準與電源產品可能主題相關，但產品額定電壓未知時，適用性仍應待確認。不能因文字相似就直接斷言必須遵循。

初篩對每份標準使用代表性原文摘錄與產品情境判讀，並非此時已逐條檢查標準全文。「檢索分數」是文字檢索排序分數，不是適用機率、符合分數或經校準的信心值。

所有標準預設選取。模型回覆失敗、低相關性及條件未知，都不會讓文件被靜默排除。請逐份檢查，若確定不應繼續比對，取消選取並填寫理由。保留／排除決策會進入歷史與匯出。

完成選取確認後開始項目比對。全庫指本機已納入的標準庫，不代表所有外部標準都已經被搜尋或檢查。使用 API 指定部分標準時，也只涵蓋該次保存的範圍。

## 6. 選擇比對方式並查看執行現況

| 模式 | 用途 | 結果界線 |
|---|---|---|
| 聚焦比對 | 先找產品候選項目與原文，再逐項判讀，適合初評與減少模型呼叫 | 若未涵蓋全部產品原文，查無證據不能當成完整產品文件未載明；重要條目應加做全量分析或人工查證 |
| 全量比對 | 每個保留的標準項目逐一掃描全部產品文字分段 | 全部文字處理完也可能有語意漏判；模型失敗與未知仍需處理 |

聚焦模式預設先檢索最多 12 個產品原文區塊。高關鍵性、關鍵性未知及待處理要求會改掃全部產品原文；候選比對找不到證據時亦會擴大查核。只檢查部分原文時，系統不會宣告已完整符合，覆蓋仍會明示。單位換算與條件等價由模型判讀，沒有獨立的確定性單位換算引擎。

執行現況會顯示目前階段、工作位置、模型請求等待時間、最近回覆與事件。進度按實際完成工作更新，不使用估算動畫當作模型正常運算的證明。

- 第一次回覆前進度停在 0%，可能正在等待第一個模型請求；先查看目前階段與等待時間。
- 「最近模型回覆」指 API 實際返回；回覆是否可解析、引文是否有效仍需後續檢查。
- 「狀態連線」只代表瀏覽器可連到本機應用程式，不能單獨證明模型正在運算。
- 停止會在目前模型請求結束或逾時後生效；已完成資料保留。
- 若程式中斷，重新啟動後查看工作狀態並使用續跑。已完成資料不應重複產生。

Portable 單次模型請求預設最多 600 秒，不是整批工作只能執行 10 分鐘。計時不等於 token 速度，也不是剩餘工時估算。請先以少量代表文件量測再安排大量分析。

## 7. 閱讀差異、風險與待補證據

| 狀態 | 代表意義 |
|---|---|
| 符合 `match` | 文字證據支持要求；仍需確認引用條件與型號 |
| 部分符合 `partial` | 只有部分要求滿足或仍有差異 |
| 不符合 `mismatch` | 有可核對的產品證據與要求衝突 |
| 文件未載明 `missing` | 在符合完整查核條件下仍缺證據；不等於實體產品失效 |
| 待確認 `uncertain` | 適用條件、來源、模型回覆或證據覆蓋不足，尚不能可靠判定 |

先看高優先度及關鍵要求，再查待補證據與未知項目。風險欄位提供覆核優先度與理由；它不是事故發生機率，也不是正式 FMEA 或 RPN 計算。安全／強制等關鍵性須有來源或人工判斷依據；**未知不能當作低風險**。

待補證據可能是產品規格漏寫、未提供測試報告、條件不一致或本次檢索未涵蓋。處置可以是補文件、詢問供應商、安排測試或改用全量分析，不能直接把缺證據改為符合。

「已選範圍完成」與「完整覆蓋」不同：所有選取項目完成全文比對，只表示選取範圍完成；若排除過任何標準，整體覆蓋仍不算完整。未解析項目另列數量，不會因流程跑完就自動消失。

「未對應產品項目」列出目前沒有建立對應的產品規格。若分析排除了文件、只做聚焦比對、尚未完成或模型判定有疑義，尤其不能把它解讀成「所有標準都沒要求這項功能」。

## 8. 人工覆核與紀錄

1. 開啟一筆結果，閱讀標準原文、獨立項目、產品引文、條件、例外及比對覆蓋。
2. 確認原判定，或修改符合狀態／風險優先度；填入姓名和說明。
3. 更正、調整風險及重新開啟須記錄原因。若要求補件，在意見中寫明缺哪份文件或哪個測試。
4. 儲存後查看歷史。原始 AI 判定保留，不會因人工改判而消失。
5. 若提示版本衝突，重新整理最新紀錄再確認，避免覆蓋其他頁籤的修改。

文件項目修改、範圍排除與結果覆核是不同歷史。覆核者姓名為自填，並無登入驗證或數位簽章；正式品質簽核請沿用公司既有流程。

## 9. 匯出與交接

| 格式 | 建議用途 |
|---|---|
| HTML | 直接以瀏覽器閱讀相關標準、風險、差異、來源及歷程 |
| Excel | 分工整理、篩選清單及會議討論；修改 Excel 不會回寫系統 |
| JSON | 保存結構化分析快照及稽核資料，供進一步處理 |

報告保留未完成／未覆核狀態、排除標準與理由、比對覆蓋、待補證據、未對應產品及原文。匯出會封存當時的版本與 SHA-256；後續改判要重新匯出，既有檔案不會自動更新。

完整報告會整理所有原文與項目快照，數百份長標準可能產生很大的檔案，匯出時也會使用較多記憶體；請保留足夠空間並等待完成，避免連續重複點下載。

JSON 不能一鍵匯回成可續作資料庫，也不包含所有原始二進位附件。完整交接與災難還原須備份整個 `data`；模型則保留在 `models`。

## 10. 舊版工作、備份與排錯

從 `/classic` 開啟舊版專案、示範、比對與覆核。示範採固定規則，不呼叫本機模型，不能用作模型品質驗收，也不能匯入正式文件庫。

要把現有專案用於新版：

1. 在「標準文件庫」按 **「匯入舊版專案文件」**，選擇原專案。
2. 按「匯入產品與標準文件」。系統沿用已保存的原檔；不用重新選取或上傳數百份文件。
3. 新加入的標準執行獨立項目抽取、核對及確認；產品亦採相同步驟。若相同內容及角色已在新版庫，會重用既有文件與狀態。
4. 在「產品與分析」選擇產品建立新版分析。原來的比對、人工覆核與報告仍保留在 `/classic`，不會被改寫。

若原始附件缺失，先還原完整 `data` 備份；只保留資料庫或匯出報告不足以完成搬移。舊版的原文確認不會直接當成新版獨立項目已經確認。

備份前先結束或停止工作，再執行 `Stop.bat`。保留整個資料夾；更新只需新程式 ZIP，將舊的 `data` 與 `models` 複製到新版，詳細步驟見 [Portable 更新指南](WINDOWS_PORTABLE.md#更新備份與搬移)。

| 遇到的情況 | 處理方式 |
|---|---|
| 文件抽取留下大量待處理項目 | 先查看原文與錯誤；可能是字數、回覆格式、模型能力或來源品質，不要直接確認為無要求 |
| 未知／待確認標準很多 | 補用途、環境、市場與標準範圍；未補齊前保留文件 |
| 相關性高但有很多不符合 | 兩者不矛盾；相關性說明值得檢查，不保證符合 |
| 聚焦比對沒有找到證據 | 檢查覆蓋，人工查閱全文，或以相同文件另建全量分析 |
| 很多引文被拒絕 | 核對模型 JSON 回覆、來源區塊與原文；不能放寬為任意改寫也算引用 |
| 服務顯示中斷 | 重新 `Start.bat`，查看工作與已完成資料，再續跑 |
| 更新後看不到舊專案 | 確認完整 `data` 已搬移，再到 `/classic` 查閱；不要刪掉舊版資料夾 |
| 想換模型重新評估 | 保留原分析，以相同文件與新模型建立新分析，勿將新舊結果混為同一批 |

正式導入前，依 [驗收清單](ACCEPTANCE.md) 使用真實代表文件及人工答案，分別檢查抽取完整性、相關標準召回、關鍵差異與覆核工時。

## 規範連結與外網完整成果（v0.3.2）

「標準文件庫」保留檔案上傳，另可貼上公開 HTTPS 規範連結。若已在外網用 ChatGPT 整理，按「匯入 ChatGPT 完整成果」，選 .standard.json 或成果下載連結，預覽後匯入並逐項確認。不必先匯入原 PDF 或建立萃取包；partial 成果只能預覽，補齊後才可匯入供分析。詳見 [完整操作流程](LINK_IMPORT.md) 與 [專用 Prompt](CHATGPT_EXTERNAL_LINK_PROMPT.md)。
