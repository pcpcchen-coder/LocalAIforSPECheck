# 從規範連結到 ChatGPT 完整成果

適用 v0.3.2 以上。你可以在外網把標準整理好，只把成果帶回公司；**不必先從公司上傳檔案給 ChatGPT，也不必先在本機建立萃取包。** 產品規格與後續產品比對仍在本機。

## 建議的操作方式

1. 在可使用 ChatGPT 的外網環境，開啟 [外網專用完整 Prompt](CHATGPT_EXTERNAL_LINK_PROMPT.md)，複製全部內容。
2. 把 Prompt 的「規範下載網址」換成一份規範的網址，填入已知名稱／版本，再交給 ChatGPT。若來源無法直接讀取，在允許的環境下載同份文件後提供附件；不要把機敏產品規格附上。
3. ChatGPT 依 Prompt 讀取原文、拆成獨立要求，產出 **`文件名稱.standard.json`**。每份規範各一個檔，確認涵蓋範圍是 complete，並核對有沒有缺頁、表格、圖示或附錄。長文件可以分輪工作，但最後要合併為同份完整 JSON；系統不會把數個 partial 自動拼成完整標準。
4. 下載成果，依公司允許的方式帶回工具電腦。也可將非機敏成果放在你有權使用且公司允許下載的位置，取得直接下載連結。系統不會替你發布成果或建立公開網址。
5. 開啟「標準文件庫」→ **「匯入 ChatGPT 完整成果」**。
6. 選「選擇已下載的成果檔」，或切換到「貼上成果檔下載連結」。填入匯入人員、實際使用的外部模型及備註。
7. 按 **「檢查並預覽」**。畫面顯示處理時間、原文區塊數、項目數、待處理數、涵蓋範圍與前 10 筆引文。預覽不寫入文件庫。
8. 確認提醒，按 **「匯入文件庫，開始人工確認」**。系統保存完整來源 JSON、原文區塊、逐項要求、檢查碼與操作紀錄。相同 JSON 內容重複匯入會開啟既有文件，不覆寫已完成的人工確認。
9. 對照原始規範核對轉錄、數字／單位、適用條件、例外、測試方法與跨章引用。完成後按「確認此份文件」，即可供產品分析沿用，不必再執行一次標準的本機抽取。

在畫面也可直接按「下載外網專用 Prompt」。ZIP 內的 `docs/CHATGPT_EXTERNAL_LINK_PROMPT.md` 與 repo 的版本相同。[合成完整成果範例](../examples/external-extraction/complete.standard.json) 可直接用於演練；它不是任何真實標準。

## 只想把規範檔案下載進本機

在「標準文件庫」的 **「或貼上規範檔案連結」** 貼上公開 HTTPS 檔案網址，按「從連結下載並匯入」。如果網址最後沒有副檔名且站台未提供檔名，請在選填檔名欄填 `規範.pdf` 等正確名稱。

支援 PDF、DOCX、XLSX、CSV、TXT、MD，每份 30 MB。匯入使用與原本上傳相同的解析器、同內容去重與人工確認流程；**此按鈕只下載及解析原文，不會自動交給 ChatGPT 或完成語意萃取。** 掃描 PDF 仍需可讀文字／OCR。

## 哪些網址可以用

| 來源 | 使用方式 |
|---|---|
| 直接回傳 PDF／DOCX／文字檔的公開 HTTPS 網址 | 貼到「規範檔案連結」 |
| 直接回傳 `.standard.json` 的公開 HTTPS 網址 | 貼到「完整成果」視窗的成果檔連結 |
| GitHub 檔案頁 | 使用 Raw 下載網址；一般 `blob` 頁是 HTML |
| ChatGPT 對話／分享網址、需登入的雲端預覽頁 | 不是本工具可直接讀取的成果檔；先在外網下載成果，再選擇檔案匯入 |
| 需帳號密碼、企業單一登入、特殊下載程式或網頁 JavaScript 的站台 | 本版不代登入、不使用瀏覽器 Cookie；請取得允許下載的檔案 |
| 公司無法連外，或必須透過企業 Proxy 才能下載 | 在允許連線的環境取得成果，再依公司核准方式搬入；本版下載器不使用系統 Proxy |

僅 HTTPS、443 連接埠；最多 3 次重新導向。下載連線／讀取有逾時與大小限制，失败时提示重试或改用檔案。重新導向的每一站都會檢查公開 IP，拒絕本機／內網／特殊用途位址。原規範 source_url 只是成果中的來源標記，匯入 JSON 時不會自動連線該網址。

## 成果驗證能保證什麼

- 必要欄位、型別、唯一區塊 ID、項目主引文及跨區塊引文必須通過檢查；沒有被引文涵蓋的原文會補為待處理。
- 每檔 16 MB、最多 2,000 區塊、20,000 個外部項目；每區塊 200 項、12,000 原文字元。系統補出的未涵蓋片段另列待處理。
- **原文由外部模型轉錄。引文存在於成果 JSON，不代表與原始 PDF 完全相同，也無法靠它偵測原 PDF 被漏掉的整頁。** 系統會明確顯示此限制，coverage complete 也仍是外部填報聲明。
- partial 成果可以保存供查看，但單份與批次確認均會拒絕，因此不能納入產品分析。請在外網補齊後匯入完整成果；這會成為新文件，不覆寫舊工作成果。
- 模型身分由匯入者填寫；不知道版本就填「ChatGPT（版本未知）」。系統不把它當作模型簽章。
- 連結預覽後，保存時會重新下載並核對內容及操作資料；檔案改變會要求重新預覽，避免保存與預覽不同的內容。
- 下載來源紀錄移除 URL 的 query 與 fragment；檔案本身仍按原樣留存。請不要在成果內容或 URL 路徑中放入金鑰。

## 與舊版萃取包的差別

| 格式 | 起點 | 匯入入口 | 可否直接帶到新資料庫 |
|---|---|---|---|
| `.standard.json` 完整成果（本頁） | 外網的規範連結／附件 | 標準文件庫 → 匯入 ChatGPT 完整成果 | 可以，檔內自帶原文與項目 |
| `.result.json` 批次結果 | 本機已解析文件及匯出的 source/input | 原文件 → 外部模型萃取 → 選原萃取包 | 不可以，須符合原 document_id／package_id |

舊流程仍可使用，詳見 [分批外部萃取指南](EXTERNAL_EXTRACTION.md)。新流程較適合公司不能對外上傳檔案的情境；舊流程的引文則可與本機事先解析的原始文件文字直接核對。

## Windows 更新

下載 [最新 Portable ZIP](https://github.com/pcpcchen-coder/LocalAIforSPECheck/releases/latest)，按 [更新步驟](WINDOWS_PORTABLE.md#更新備份與搬移) 沿用原本 `data` 和 `models`。模型仍獨立下載，不會重新包入 ZIP。新功能無新增 Python 套件。匯入 API 本身不呼叫本機模型；既有 `Start.bat` 仍會啟動模型服務，產品抽取與比對需模型就緒。
