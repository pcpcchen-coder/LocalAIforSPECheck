# 驗收與真實模型評估

分開驗證「軟體流程正確」與「模型對真實規格判斷足夠可靠」。內建示範與模擬 API 的測試，不能代表任何本地模型的準確率。

## A. 可重現的自動測試

在虛擬環境執行：

```bash
python -m pip install -r requirements-dev.txt
python -m pytest
```

具體案例以 `tests/` 實際內容及執行輸出為準。任何未實跑的平台、模型或案例都不應標記已通過。

## B. 基本作業驗收

| 編號 | 操作 | 通過標準 |
|---|---|---|
| B01 | 雙擊作業系統啟動檔 | 開啟本機瀏覽器；預設網址 127.0.0.1:8765 |
| B02 | 服務開啟時再次雙擊 | 開啟既有頁面，不重複啟動另一個服務 |
| B03 | 用其他程式占用端口後啟動 | 顯示端口被占用，不終止其他程式 |
| B04 | 建立內建示範並執行 | 不需要模型；結果清楚標記為示範 |
| B05 | 建立專案，上傳產品及兩份規範 | 每份文件有角色、原檔、擷取位置與警告 |
| B06 | 未確認擷取便開始比對 | 拒絕開始；明確要求先確認來源文字 |
| B07 | 上傳掃描／圖片型 PDF | 顯示缺少文字或解析限制，不默默產生「全部符合」 |
| B08 | 上傳錯副檔名、損毀或超過 30 MB 檔案 | 提供可理解錯誤，不留下假文件項目 |
| B09 | 完成一份多規範比對 | 每個規範區塊有結果；可以篩選差異與覆核狀態 |
| B10 | 打開來源與證據 | 每則有效引述可在所引用產品區塊查到，位置可追溯 |
| B11 | 各匯出 HTML／XLSX／JSON | 全部結果與未覆核項目保留；沒有 API key |
| B12 | 在匯出資料放入 HTML 標籤或 Excel 公式文字 | 作為文字保留，不能執行腳本／公式 |

## C. 覆核與恢復驗收

| 編號 | 操作 | 通過標準 |
|---|---|---|
| C01 | 確認 AI 判定 | 原 AI 判定保留，新增一筆具姓名、時間、版本的事件 |
| C02 | 更正並填寫理由 | 最終狀態改變；排序使用有效人工判定 |
| C03 | 空白理由更正 | 拒絕儲存並提示原因 |
| C04 | 填原因後重新開啟 | 回到待覆核、有效判定回到 AI 原值、歷史保留 |
| C05 | 同一列在兩頁籤從相同版本先後送出 | 第二次衝突得到 409／畫面提示，不能覆寫第一筆 |
| C06 | 查看覆核歷史並再匯出 | 依版本可還原確認→更正→重新開啟過程 |
| C07 | 比對中取消 | 等本次 HTTP 返回後停止；已完成列保留 |
| C08 | 取消後續跑 | 跳過已保存列，未完成列重新執行，不產生重複結果 |
| C09 | 比對中退出再重新開啟 | 上次工作標記中斷，可續跑；舊結果與覆核不遺失 |
| C10 | 修改模型設定後續跑舊比對 | 使用原 Run 的模型與參數快照；換模型須另建比對 |
| C11 | 移除產品、上傳新版並重新比對 | 舊 Run 的文件快照、結果及原檔仍可追溯 |
| C12 | 停止程式，備份並還原整個資料目錄 | 專案、原檔、結果、設定及覆核歷史完整恢復 |
| C13 | 匯出，修改覆核，再匯出一次 | 留下兩份紀錄與各自 SHA-256；重新下載第一份仍與初次位元組完全相同 |
| C14 | 查看 Run 來源快照 | 可找到模型參數、文件雜湊、提示詞版本與雜湊 |

## D. 真實模型上線前驗收

選擇至少一份可對外使用的代表性產品文件，以及兩份與實際工作難度相近的規範。由兩名熟悉產品的工程師先建立人工基準，意見不同先協調確認，避免拿未審核的 AI 結果當標準答案。

人工基準至少涵蓋下列情境：

- 數值相同、數值不同、上下限與容許公差。
- 單位等價及換算，如 `0.1 kV` 與 `100 V`。
- 包含／未包含範圍，如工作溫度要求與產品額定區間。
- 必須符合的多個條件，其中只有一項不符合。
- `and`／`or`／除外條件／僅在特定模式適用。
- 數值在表格、證據在後文、或產品不同段落存在矛盾。
- 要求未載明與確實不符合的區別。
- 圖片／掃描／公式／註腳中存在重要條件，純文字不完整。
- 型號、測試條件、版本與引用標準不同。

建議基準至少 50 個人工拆分的原子條件，保留每項來源位置、預期狀態、產品證據與關鍵性。這是起始驗收規模，不足以推估所有文件的表現。

| 指標 | 算法／記錄內容 | 建議起始門檻 |
|---|---|---|
| 結構處理覆蓋 | 有結果的規範區塊／全部規範區塊 | 100%；模型失敗須仍保留待確認列 |
| 原文證據可追溯 | 可在引用位置核對的引述／全部引述 | 100%；不符者不能維持肯定判定 |
| 原子差異召回率 | AI 找出的人工已知差異／人工基準全部差異 | 先以 ≥95% 作試用門檻，依風險提高 |
| 關鍵差異漏判 | 關鍵差異被判為符合或未提示 | 此驗收樣本內 0 件；不能外推為未來零漏判 |
| 狀態一致率 | 與人工基準一致的項目／可對應項目 | 記錄各類混淆，門檻由品質負責人設定 |
| 待確認比例 | 待確認項目／全部結果 | 記錄原因，不能為降低比例而強行改成符合 |
| 處理成本 | 總耗時、模型呼叫數、RAM／GPU 峰值 | 依同仁可接受工時與硬體設定 |
| 人工覆核時間 | 每份文件人工基準工時與工具輔助工時 | 實測，再決定是否擴大使用 |

規範一個區塊含多個原子條件時，評估召回率須由人工逐條對應，不能直接用程式的區塊數代替。不同模型、量化版本、context 長度、提示詞或服務版本改動後，應重跑代表性樣本。
