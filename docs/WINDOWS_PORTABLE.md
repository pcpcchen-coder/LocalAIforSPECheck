# Windows 免安裝版操作指南

這份指南適用於 **Windows 10／11、64 位元 x64** 電腦。完整 Portable ZIP 內附 Python、所有 Python 套件、CPU 模型服務及 **Qwen3.5-2B Q6_K** 模型；下載完成後，解壓縮即可在單機執行，不需要安裝 Python、LM Studio、Bionic 或額外模型服務。

若公司的規定也禁止執行下載的 EXE，仍須由 IT 核准使用。可攜版不需要管理員權限，但不會繞過公司的端點控管。

## 第一次下載

1. 開啟 [GitHub 發佈頁](https://github.com/pcpcchen-coder/LocalAIforSPECheck/releases)。
2. 在最新版本的 **Assets** 下載 **`LocalAIforSPECheck-Windows-x64.zip`**，也可使用 [完整 ZIP 下載連結](https://github.com/pcpcchen-coder/LocalAIforSPECheck/releases/latest/download/LocalAIforSPECheck-Windows-x64.zip)。檔案內已包含模型，因此下載量超過 1 GB。
3. 等候下載完成。不要選 `Source code (zip)`，也不要使用專案首頁綠色 **Code → Download ZIP** 來替代；那些檔案只有原始碼，不能直接執行。
4. 在下載的 ZIP 按滑鼠右鍵，選 **全部解壓縮**，選擇自己可以寫入的本機資料夾，例如「文件」中的 `規格比對工具`。
5. 解壓完成後，開啟裡面的 `LocalAIforSPECheck-Windows-x64` 資料夾。確認能看到 `Start.bat`、`Stop.bat`、`Choose_model.bat`，以及 `runtime`、`app`、`engine`、`models` 等資料夾。

**請先完整解壓縮再執行。** 不要直接在 ZIP 視窗內雙擊啟動檔，也不要只把 `Start.bat` 拉出來。各資料夾需要放在一起。

建議使用有 **16 GB 記憶體**的電腦，並保留 **10 GB 以上可用磁碟空間**供 ZIP、解壓後程式、文件及備份使用；這是工作餘裕建議，並非實測的硬性最低需求。內附引擎以 CPU 執行，速度會依電腦而異。Windows ARM、32 位元 Windows 及網路共用磁碟不是此套件的支援目標。

若要核對下載是否完整，請由熟悉電腦的同仁將 ZIP 的 SHA-256 與同版 Release 的檢查碼檔比對；可在 PowerShell 執行：

```powershell
Get-FileHash .\LocalAIforSPECheck-Windows-x64.zip -Algorithm SHA256
```

## 每天如何開始

1. 進入完整解壓的資料夾，雙擊 **`Start.bat`**。
2. 保持啟動視窗開啟，等待模型載入。第一次或較慢的電腦可能需要數分鐘；啟動器最多等候模型載入 5 分鐘。不要連續重複啟動。
3. 瀏覽器會自動開啟本機比對頁面。如果沒有自動開啟，將啟動視窗顯示的 `http://127.0.0.1:...` 網址貼進瀏覽器。
4. 內附模型已由啟動器設定連線，可直接操作。不需要註冊雲端模型帳號，也不需要填入 OpenAI API key。

預設頁面網址是 `http://127.0.0.1:8765`；該連接埠若已被占用，啟動器會改用其他可用連接埠，請以視窗顯示的網址為準。它不會關閉占用連接埠的其他程式。

這個網址只在自己的電腦使用，不是公司共用網站。不要將網址傳給同仁期待他們直接開啟同一個專案；交接請用報告或完整備份。

## 先試一次操作

1. 使用首頁的範例示範入口。
2. 查看不同規範的排序，點開一筆結果，閱讀「技術規範原文」與「產品文件證據」。
3. 在「記錄人工確認」填入姓名與意見，選擇確認或修正，按「儲存本次確認」。
4. 到「匯出與追溯」，下載一份 HTML 報告，再以瀏覽器開啟，查看差異與確認歷程。

這個**示範採固定規則，不會呼叫模型**，只用來熟悉頁面與覆核流程。它通過不代表模型已適合公司的正式文件。

## 用自己的文件正式比對

1. 按「建立專案」，輸入容易辨認的名稱，例如 `控制器A_2026規範初評`。
2. 匯入**一份產品規格**，再匯入**一份或多份技術規範**，為每份選擇正確角色。
3. 逐份按「預覽並確認」。對照原始文件，核對文字、數字、單位及表格，再勾選確認聲明，按「確認原文，可用於比對」。
4. 選擇要比較的規範，按「開始本機模型比對」。第一次請先用短文件，確認可完成及判斷合理後再處理長文件。
5. 第三步驟查看執行現況：目前規範與區塊、產品文字視窗、模型請求等待時間、最近回覆及近期事件。已完成列可先行覆核；完成後再查看「文件符合度參考分數」及全部結果。分數只是初篩排序，不能取代關鍵條款的人工判斷。
6. 逐筆閱讀規範與產品證據。若不認同 AI 判定，選「修正判斷」、選正確狀態、填入姓名和依據，再儲存。
7. 需要重新確認時可選「重新開啟，待確認」。每次動作會新增歷程，保留原始 AI 判定及先前確認紀錄。
8. 到「匯出與追溯」下載 HTML、XLSX 或 JSON。報告包含未確認項目；覆核後請重新匯出，舊報告不會自動更新。

內附 **2B 模型供入門與初篩**，對複雜條件、例外、單位換算及跨段引用仍可能誤判。正式採用前，請用公司代表性文件建立人工答案並評估；所有結果均須人工覆核。模型引用到原文，也不等於推論正確。

支援有文字層的 PDF、DOCX、XLSX、CSV、TXT、Markdown，單檔上限 30 MB。**沒有內建 OCR**；掃描 PDF、圖片表格與圖面須先用核准工具轉成文字並人工核對。舊式 DOC／XLS、加密文件不能直接使用；不要只更改副檔名。完整流程見 [同仁操作指南](USER_GUIDE.md)。

## 第三步驟：怎麼知道有沒有在執行

開始比對後，執行現況區塊會顯示目前處理階段與工作位置，並列出模型請求、經過時間、最近回覆、連線更新與近期事件。

- **百分比不動，但產品視窗或近期事件有更新：** 目前規範區塊尚未全部完成。只有完整處理並儲存一列，完成百分比才會增加；第一列很長時可能暫時停在 0%。
- **顯示等待模型回覆：** 請看目前請求已等待多久。內附模型以 CPU 運算，長文件可能要等數分鐘；預設單次請求上限是 600 秒（10 分鐘），不是整個批次只能執行 10 分鐘。
- **連線正常但很久沒有新回覆：** 本機程式仍可回傳狀態，但不能據此確認模型正在運算。可查看啟動視窗與 `logs/model.log`；第一次請先用短文件確認速度。
- **顯示狀態連線中斷或更新過久：** 目前呈現的是最後收到的狀態。先確認啟動視窗沒有關閉，必要時依下方停止與重啟步驟處理；不要反覆按開始比對。
- **已按停止、仍在等待：** 停止請求已記錄；目前模型請求須返回或逾時才會結束後續處理。已完成的結果會保留。

畫面的時間增加不等於模型仍在運算；工具不會顯示無法取得的 token 速度、CPU 使用率或預估完成時間。詳細欄位說明見 [同仁操作指南：啟動比對並查看進度](USER_GUIDE.md#5-啟動比對並查看進度)。

## 如何停止

1. 等待比對完成；若不想繼續，先在頁面按「停止比對」，等待目前請求結束及狀態更新。
2. 回到解壓資料夾，雙擊 **`Stop.bat`**，等待服務停止。
3. 關閉瀏覽器頁面即可。下次雙擊 `Start.bat`，既有工作資料仍會保留。

關閉瀏覽器並不等於停止模型或程式。搬移、備份或更新前一定要先停止；若直接執行 `Stop.bat` 時仍有比對進行，或電腦突然中斷，當前請求可能未完成；重新啟動後可查看已完成列，並對未完成批次使用「繼續未完成項目」。

## 換用較大的模型

若公司的文件較複雜，請由熟悉模型的同仁先評估 [模型建議](MODELS.md)。較大的模型需要更多記憶體，CPU 比對也可能明顯變慢。

1. 在允許下載的電腦取得相容的 **GGUF 文字模型**。一次只下載需要的量化版本；不要把整個模型庫所有檔案都下載。
2. 在工具電腦先雙擊 `Stop.bat` 並等待停止。
3. 將完整的 GGUF 檔案複製到解壓資料夾中的 **`models`**。請保留原本的入門模型，以便需要時切回。
4. 雙擊 **`Choose_model.bat`**，輸入清單上的模型編號並按 Enter；直接按 Enter 可取消。選擇在下次啟動生效。
5. 重新雙擊 **`Start.bat`**，用小份代表文件執行本機模型比對，確認格式、速度與判斷，再逐步增加工作量。

建議先評估 Qwen3.5-9B Q4_K_M／Q6_K。27B 等較大模型需有足夠記憶體，並另行確認內附引擎對該模型架構的支援；「副檔名是 GGUF」不代表每一種模型都能載入。此版以單一 GGUF 權重檔為選擇對象，不提供分片模型的自動合併、模型下載或 GPU 後端安裝。

啟動時會計算 GGUF 的 SHA-256 指紋，並隨本機比對保存。中斷批次只能使用原本名稱及相同內容的模型續跑；若重啟時連接埠改變，系統會記錄續跑位址並保留原始快照。

模型變更不會重新計算舊結果。若要比較新舊模型，請保留舊批次，使用相同文件建立新的比對，並重新人工驗收。

## 更新、備份與搬移

| 資料夾 | 內容 | 使用者應如何處理 |
|---|---|---|
| `data` | 原始文件、資料庫、模型設定、比對、人工歷史、歷次報告 | 重要工作資料；完整備份，不要任意刪改 |
| `logs` | `app.log`、`model.log`，以及上一次啟動的 `*.previous.log` | 排錯時提供經檢視的內容；可能包含路徑等資訊 |
| `models` | 入門模型與自行新增的 GGUF | 保留選用模型，更換電腦時一併搬移 |
| `app`、`runtime`、`engine` | 程式、Python 與模型執行服務 | 維持原目錄結構，不需手動安裝或搬動內部檔案 |

**備份或搬移：**先停止程式，完整複製整個 `LocalAIforSPECheck-Windows-x64` 資料夾。另一台相容的 Windows 電腦從該資料夾啟動，即可保留模型及工作資料；該電腦也必須允許執行可攜程式。不要只複製 HTML 報告來當作可續作備份。

**更新：**

1. 在舊版按「停止比對」並等待狀態更新，再雙擊 `Stop.bat`，確認服務停止。
2. 完整備份舊版資料夾。新版完整 ZIP 解壓到**另一個新資料夾**，不要覆蓋正在使用的舊版。
3. 閱讀該版 Release 的相容性說明。v0.2.1 的執行現況功能沿用既有資料庫，無須重新匯入文件或安裝新軟體。
4. 將舊版**整個 `data`** 複製到新版；其中包含資料庫、原始文件、覆核紀錄、報告及 `portable-config.json` 模型選擇設定。不要只複製單一 SQLite 檔。
5. 若有自行增加的 GGUF，也將那些模型檔複製到新版 `models`，並保留原檔名。新版已內附的入門模型不必從舊版重複複製。
6. 啟動新版，確認專案、覆核歷史及模型選擇正常；瀏覽器若仍顯示舊介面，按 `Ctrl+F5` 重新載入。舊批次沒有的新進度欄位會顯示未記錄，原結果仍可使用。
7. 確認後再封存舊版。不要同時啟動兩個資料夾，避免把新工作做在不同份資料庫；若要退回，使用升級前保留的完整備份。

未來版本若另有資料轉換要求，請以該版 Release 說明為準。

原始文件、比對結果、日誌與匯出均可能含機密資料。備份請依公司文件權限保存；不要把工作資料夾上傳公開 GitHub。

## 遇到問題時

| 現象 | 先做這件事 |
|---|---|
| 找不到 `Start.bat` 或 `runtime` | 核對是否下載完整 Portable ZIP，並完成「全部解壓縮」；Source code ZIP 不是可執行包 |
| Windows 或公司防護拒絕執行 | 保留提示文字與 Release 來源，交由 IT 核准；不要停用防毒或繞過公司政策 |
| 顯示無法寫入檔案 | 將完整解壓資料夾移到自己可寫入的本機位置；避免系統目錄、唯讀磁碟與網路共用磁碟 |
| 模型久久沒有載入／記憶體不足 | 關閉不需要的程式，查看啟動視窗與 `logs`；若剛換大模型，停止後切回內附 2B 再試 |
| 瀏覽器沒有開啟 | 使用啟動視窗顯示的本機網址；不要自行改成公司 IP 或外部網址 |
| 無法連線到模型 | 確認啟動視窗仍在；先停止後重新執行 `Start.bat`，查看模型載入錯誤與 `logs` |
| 能完成比對但許多列「待釐清」 | 查看各列警告；可能是模型能力、回覆截斷、逾時或文件抽取問題。不要直接改成「符合」 |
| PDF 讀不到字／表格內容錯位 | 先修正文書或以核准工具 OCR，人工核對後重新上傳；重跑模型不會修好來源抽取 |
| 上次的專案不見了 | 確認啟動的是同一個解壓資料夾；每個資料夾有自己的 `data`，不要刪除舊版 |
| 比對速度太慢 | 先測小文件、減少同時開啟的程式；大模型及長文件的 CPU 執行可能需要很久 |
| 第三步驟進度停在 0% | 查看執行現況的工作位置、模型請求及近期事件；第一個區塊儲存前，百分比不會增加 |
| 狀態連線中斷／更新過久 | 確認啟動視窗仍開啟；舊狀態和增加中的計時不是服務正常證明，先恢復服務再看最新狀態 |

Portable 版單次模型請求最多等待 600 秒。頁面中的「停止比對」會等目前請求結束才停止後續工作；若需要結束整個服務，可使用 `Stop.bat`，下次再續跑未完成項目。

向維護人員回報時，附上發佈版本、Windows 版本、記憶體容量、選用模型、操作步驟及錯誤文字即可。提供日誌前先檢視敏感內容，不要直接上傳公司產品文件。授權與組件來源見 [PORTABLE_COMPONENTS.md](PORTABLE_COMPONENTS.md)。
